# Публичная публикация прототипа через GitHub Pages

## Цель

Опубликовать текущий React/Vite-прототип «Гараж» по адресу `https://kcska18051-crypto.github.io/garage/`, чтобы главная страница и все реализованные маршруты каталога открывались без локального сервера.

## Выбранный подход

Публикация выполняется GitHub Actions из ветки `codex/homepage-prototype`. Workflow устанавливает зависимости в `prototype/`, запускает проверки, собирает Vite-приложение с базовым URL `/garage/` и передаёт папку `prototype/dist` в GitHub Pages.

Это предпочтительнее отдельной ветки `gh-pages`: собранные файлы не хранятся в рабочей ветке, а публичная версия автоматически обновляется после каждого push.

## Маршрутизация

`BrowserRouter` получает basename из `import.meta.env.BASE_URL`. В локальной разработке значение остаётся `/`, а в Pages-сборке равно `/garage/`. Поэтому существующие внутренние ссылки продолжают использовать маршруты вида `/catalog`, но браузер открывает их под префиксом репозитория.

Для прямого открытия вложенных URL после сборки создаётся `dist/404.html` как копия `dist/index.html`. GitHub Pages отдаёт этот файл для неизвестного пути, после чего React Router восстанавливает нужную страницу по текущему URL.

Обязательные публичные маршруты:

- `/garage/` — главная;
- `/garage/catalog` — общий каталог;
- `/garage/catalog/compressor-equipment` — категория первого уровня;
- `/garage/catalog/compressor-equipment/screw-compressors` — категория второго уровня;
- `/garage/catalog/compressor-equipment/oil-free-compressors` — вариант без тегов.

## Workflow публикации

Workflow размещается в `.github/workflows/deploy-prototype-pages.yml` и запускается:

- при push в `codex/homepage-prototype`;
- вручную через `workflow_dispatch`.

Он использует официальные GitHub Actions для настройки Pages, загрузки артефакта и развёртывания. Разрешения ограничиваются чтением репозитория, записью Pages и выдачей OIDC-токена для deployment.

Параллельные публикации объединяются в одну concurrency-группу; незавершённая старая публикация отменяется при появлении новой.

## Изменения приложения

Изменяется только инфраструктура базового URL и публикации. Визуальная система, данные, интерактивность, маршруты внутри приложения и локальная команда `npm run dev` сохраняются.

Для сборки Pages добавляется отдельная команда, чтобы обычная локальная production-сборка продолжала работать от корня `/`.

## Проверка

До публикации выполняются:

- unit-тесты;
- TypeScript/Vite build;
- E2E-тесты локального режима;
- проверка содержимого Pages-сборки и наличия `404.html`.

После deployment проверяются HTTP 200 и визуальная загрузка главной, каталога и вложенной категории по публичным HTTPS-адресам. Публичная ссылка считается готовой только после успешного завершения workflow и фактической доступности страниц.

## Ошибки и откат

Если Pages недоступен или workflow не получает необходимые разрешения, сначала проверяется настройка источника Pages и журнал конкретного deployment. Изменение не должно затрагивать локальный запуск. Откат выполняется удалением workflow и Pages-специфичной команды/настройки basename отдельным коммитом; пользовательский код страниц не требует отката.
