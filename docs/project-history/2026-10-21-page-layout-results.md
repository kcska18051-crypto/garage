# Общий контейнер и подвал всех страниц

## Причины и исправление

Пустой поиск использовал `container`, но этот класс не имел CSS-определения. Его заголовок начинался с левого края окна, в то время как шапка и подвал использовали общий контейнер. RED на2560: расхождение заголовка и логотипа592px.

Оболочка имела только min-height, без распределения высоты между main/footer. Короткое содержимое не отодвигало подвал вниз. Разные страницы имели несогласованные верхние/нижние padding; перед подвалом дополнительно прибавлялся margin-section.

Теперь оболочка — flex-column с min-height100dvh, основная область занимает свободную высоту, подвал остаётся в потоке (не fixed). Внутренние страницы используют существующий `--container`/`--gutter`, центрирование, одинаковый padding-block16–32px. Значения ширины дизайн-токенов не изменены. Главная сохраняет полноширинные поверхности и собственные внутренние контейнеры; популярные категории/слайдеры не переделывались.

Подвал имеет одинаковые умеренные внешние padding сверху и снизу24–32px и не добавляет лишний margin перед собой. На мобильном сохранён резерв нижней навигации и safe area только в оболочке; прежний второй резерв в подвале убран. Дополнительный RED показал: резерв72px, фактическая панель61,75px. min-height панели согласована с существующим токеном, поэтому подвал доходит до её верхней границы без лишней полоски.

## Состояние рабочей копии и способ публикации

Команды с `require_escalated` перестали запускаться (даже read-only Get-Date), поэтому зависли и были остановлены git fetch/commit и gh status; это не доказательство недоступности GitHub. Default-shell HTTPS даётEACCES, но подключение GitHub работает. Публикация выполнена атомарно GitHub API: tree на проверенной базе6fb6049 → commit9f55e1e → fast-forward update_ref с expected_sha, безforce. В main ничего не изменено.

Важно для продолжения: **локальный HEAD остаётся6fb6049**, изменения файлов соответствуют опубликованному коду. До следующих gitpush нужно fetch и аккуратная сверка/синхронизация с удалённой веткой; не делать force/reset и не терять stash пагинации. Отчёт/скриншоты/уточнение harness сохраняются отдельным API-коммитом без изменения runtime.

Для публичной проверки использованы отдельно запущенные headless Chromium1234 через браузерный сервис, со своими context/page и finally-close. Общая страница сервиса и браузер пользователя не навигировались. Обычный CLI launch браузера в сервисе сначала не нашёл штатный1247binary; использован уже установленный и проверенный1234exe, ничего не устанавливалось. Независимая аналитическая приёмка отдельно; задача404 принята следующей, маршрутизацию в этом исправлении не меняли.
