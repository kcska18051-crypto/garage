# Страница 404: маршрутизация и адаптив

## Согласованный объём

Ошибочные и несуществующие публичные адреса должны показывать компактную страницу с числом404, заголовком «Страница не найдена», пояснением и кнопками «На главную»/«В каталог». Общие шапка, поиск и подвал сохраняются. Ошибочный URL не заменяется. Новые товарные/каталожные страницы в эту задачу не входят.

## Причины и исправления

- Удалены устаревшие wildcard-заглушки `/catalog/*`, `/brands/*`, `/actions/*`, перехватывавшие ошибочные вложенные адреса.
- Неизвестная подкатегория больше не перенаправляется в корень компрессоров. Дочерний slug проверяется на принадлежность существующей подкатегории.
- Сохранены существующие проверки записей товара, материала, акции, услуги и магазина.
- Уменьшены число404, заголовок и интервалы. Убрана искусственная минимальная высота: общий flex-контейнер поддерживает положение подвала без фиксированного перекрытия содержимого.
- Добавлены пояснение, заголовок вкладки и `noindex, follow` с восстановлением метаданных при уходе со страницы. Canonical на главную не создаётся.
- Независимое source-review обнаружило ссылки на ещё не реализованные подразделы из корня/страницы направления каталога. Они оставлены как информационные подписи без перехода и стрелок. Реализованные ссылки сохранены через общий CatalogDestination на основе publicRoutes.

## Проверки до публикации

RED:5из14сценариев ошибочных URL воспроизвели неверный экран/redirect. Дополнительный RED выявил отсутствие пояснения; ещё2RED — неработающие ссылки на подразделы. После исправления routing/404 unit **27/27 GREEN**.

Production-сборка: TypeScript и buildPages успешны, **150** существующих маршрутов и404fallback. Предупреждение о bundle>500KB существовало ранее.

Отдельный headless-браузер: **136/136** сочетаний ошибочных адресов (17адресов × с/без завершающего slash ×1920/1440/390/360) показывают404, сохраняют URL/query, не имеют горизонтального переполнения; подвал не заканчивается выше viewport. Перезагрузка проверена на каждой ширине. Скриншоты осмотрены на1920/390.

Все **150/150** существующих маршрутов открыты на production-preview: ни один не стал404. Отдельно1920/390: кнопки главная/каталог, Back/Forward и поиск Remeza работают; после перехода из404 метаданные не остаются. Первый harness ожидал строго `/garage/`, но router переходит на равнозначный `/garage`; ожидание уточнено, продукт не менялся. Повтор — PASS. Source-review функционально одобрил правку, два замечания по типографике информационных карточек исправлены без изменения размеров относительно ссылок.

Первый CLI-прогон браузера и полный локальный Vitest не считаются успешными: среда Windows исчерпала память/зависла без результатов. Сборка повторена с GOMAXPROCS=2. Проверка production-preview требует явного `--base=/garage/`; неудачный запуск без этого параметра не считается ошибкой продукта. Общий браузер пользователя не использовался; собственные браузеры закрываются finally.

## Ограничения хостинга

Vite preview — SPA-сервер и может отдавать HTTP200 для отсутствующего URL, при этом приложение показывает404. GitHub Pages использует сгенерированный404.html как оболочку приложения для неизвестных прямых URL. Клиентская навигация сама по себе не меняет HTTP-статус уже загруженного документа. В будущей серверной реализации (Битрикс) неизвестные адреса должны возвращать настоящийHTTP404, существующие —HTTP200; клиентский экран это не заменяет. Неизвестные адреса не добавляются в publicRoutes или список публикации.
