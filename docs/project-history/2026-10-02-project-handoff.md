## Что готово

Ранее реализованы главная, каталог и фильтры/теги, товары, бренды, акции, поиск, корзина, сравнение, оформление заказа и основные сценарии ЛК. Подробности — в предыдущем handoff и спецификациях. Последние пакеты:

- ЛК: документы, помощь, восстановление доступа, управление адресами и связь с checkout. Исправлены FAQ и заметный переход к разным формам поддержки.
- Единый адаптивный поп-ап входа/регистрации/восстановления: SMS и пароль, регистрация компании по ИНН; переход в ЛК работает, при авторизации из checkout сохраняется исходное намерение.
- Временный демо-вход: «Профиль → По паролю → Войти», телефон и пароль не обязательны. Подсказка видна. Флаг `DEMO_PASSWORD_ENTRY_ENABLED`; после демонстрации отключить. Это не механизм безопасности будущего сайта. Пароли не хранить в localStorage/логах.
- Новости / Статьи / Обзоры: списки и детали, рубрики, сортировка, пагинация, связанные материалы, видео, входы на главной и в футере.
- Доставка / Оплата / Гарантия: единый информационный шаблон, отдельные маршруты, меню, нейтральный временный текст.
- 404: минимальная, центрирована между шапкой и подвалом, «На главную» / «В каталог». GitHub Pages может отдавать HTTP 200 для SPA fallback — это визуальная 404, не подтверждение серверного статуса.
- Контакты: три демоточки, интерактивная схема, сообщение/обратный звонок в поп-апах, валидация и адаптив. Реальной карты и отправки нет.
- «О компании»: крошки, заголовок, нейтральный текст, компактные «Ассортимент / Подбор / Поддержка». Пользователь посмотрела: вариант пока сырой, но оставить без дополнительных правок для согласования с клиентом.

## Окончательные визуальные решения (важнее ранних вариантов)

- Сохранять готовые шапку/подвал и соответствие общего контейнера; проверять широкие экраны и мобильные.
- Без гигантских hero, больших декоративных блоков и чрезмерных отступов. Крошки при этом не должны прилипать к шапке.
- Материалы: sidebar на desktop; на mobile горизонтальная внутренняя навигация. Пункты ведут в соответствующие списки, активный выделен.
- Списки: 4/3/2/1 карточки в зависимости от ширины с учётом sidebar; одинаковые пропорции обложек и читаемые анонсы.
- Детали: главные и декоративные баннеры компактные, пропорция 3:1. Видео — 16:9, одно крупное или два рядом, mobile друг под другом; без бокового демонстрационного текста. По нажатию, без autoplay; нет видео — нет пустого блока.
- Заголовки, лид, абзацы и подзаголовки выравнивать по общему левому краю основной колонки справа от sidebar. НЕ центрировать узкую текстовую колонку. Предыдущее решение центрировать текст отменено.
- Оглавление/«Содержание» удалено; вместо него обычный текст. Это отменяет прежнее требование якорей длинной статьи.
- «Что изменилось» и «Практическое применение» убраны; нейтральный текст, без выдуманных фактов. «Читайте дальше» сохранено.
- Анонс и деталь имеют согласованные заголовок, дату и смысл вводного текста. Во всех типах материалов предусмотрены примеры с видео и без него.
- События — пока рубрика новостей, не отдельная структура.

## Осталось по прототипам — услуги

Логика обсуждена; последнее сообщение было аналитическим предложением, пакет услуг ещё НЕ передан в разработку и не объявлен принятым. Согласовать ТЗ и запуск с пользователем.

1. Первый уровень «Все услуги»: три компактных анонса — «Подбор автоэмали», «Сервисный центр», «Аренда оборудования/инструментов». Предусмотреть больше направлений в будущем.
2. Второй уровень: список услуг внутри направления, как каталог, с названием/кратким текстом/блоком цены/переходом. Реальные цены не выдумывать.
3. Общая детальная страница услуги: крошки, название, компактная иллюстрация, описание, стоимость/заглушка, кнопка заявки.
4. Поп-ап заявки: поля, валидация, явный демонстрационный успех, будущая связь с «Заявками на услуги» в ЛК подлежит согласованию.

Из протокола: сервисный центр и аренда ждут структуры клиента. Аренда компрессора — вложенная услуга аренды, не четвёртое направление. Для подбора автоэмали предусмотрены 4–5 подкатегорий; отдельно упомянуты подбор по образцу и полиуретановые краски (положение последних уточнить).

Референсы: https://kolerovki.net/services/kolerovka/ ; https://avtokraski.ru/services/podbor-avtoemaley/ ; https://yaroslavl.bigam.ru/services/ ; список по принципу Кувалда. Bigam при последнем веб-чтении не открылся — не утверждать, что изучен полностью.

На Колеровки.Нет найдены пять позиций для предварительного набора: колеровка автоэмали, подбор по цветовому вееру, налив краски по коду, изготовление краски для царапин, заправка краски в баллончики. В протоколе есть пожелание взять их названия как стартовые, потом клиент уточнит. Не переносить чужие цены, фактические условия и большие тексты. Для сервиса/аренды допустимы только явно демонстрационные примеры до клиентской структуры.

## Другие открытые вопросы

- В «прототипы» остался вопрос по hover-меню: выпадающее содержимое только у кнопки «Каталог» или также у каждого пункта нижней строки шапки? Ответ пользователя в этом аналитическом чате не получен. Не выбирать расширение самостоятельно.
- Ранее выявлялась потеря адресов после reload; исправление persistence было передано. Итоги последующих пакетов подтверждают CRUD/sync, но в этом чате отдельная финальная проверка reload после фикса не зафиксирована — проверить точечно, не считать это новым основанием повторять весь архив тестов.
- Политика конфиденциальности — отдельная заглушка `/privacy`, не готовый юридический документ.
- Финальная визуальная приёмка и утверждение реального наполнения — клиентские действия. Не объявлять все страницы принятыми лишь по зелёным тестам.

## Ограничения и работа дальше

- Это интерактивный прототип, не готовый production/backend. Контакты/тексты/карта/отправка форм/авторизация — демонстрационные.
- Реальные сведения, сроки, регионы, гарантии, документы и цены предоставляет клиент. Не выдумывать обязательства.
- CMS планируется 1С-Битрикс; интеграции, серверная авторизация, настоящие SMS/формы/карты и юридические документы — отдельный этап.
- Категории/автотеги формируются из свойств товаров с настройкой по категории; вывод фильтров регулируется отдельно, SEO-индексация отдельно. Счётчики у быстрых тегов убраны, результат выдачи может иметь количество.
- Автоописание только для детального текста при отсутствии исходного описания: шаблоны из подтверждённых свойств, без AI и выдуманных характеристик; готовый исходный текст приоритетен. Детали — аналитическая история/проектная документация.
- Лояльность скрыта до согласования, «Спасибо» не добавлять. Код подтверждения для другого получателя — вопрос клиента.
- Пользователь просит экономить токены: этот конспект + релевантные спецификации, не перечитывать весь чат/репозиторий, краткие отчёты.
- Автоматизации `automation`, `automation-2`, `404` завершили передачи и приостановлены; не возобновлять старую очередь автоматически на рабочем компьютере.
