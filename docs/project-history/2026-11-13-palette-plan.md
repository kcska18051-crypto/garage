# Единая палитра — 13 ноября 2026

Палитра и внедрение согласованы пользователем в чате. Дополнительно: у залитых кнопок нет цветной окантовки. Подвал отложен, его оформление сохраняется.

## Правила

- Белый `#FFFFFF`, поверхность `#F5F5F5`, границы `#E5E5E5`.
- Текст `#242424`, подписи `#6B6B6B`.
- Каталог, подбор, заявки и обычные основные действия: `#FFCC00`, hover `#FFD633`, графитовый текст.
- Покупка и оформление: `#C92F29`, hover `#B72823`, белый текст.
- Второстепенные действия: белый фон, нейтральная рамка, hover рамки `#8A8A8A`.
- Выбранные параметры: белый фон / жёлтая граница; вкладки с подчёркиванием там, где это соответствует существующему компоненту.
- У залитых кнопок прозрачная граница той же толщины, без цветного inset-shadow. Это сохраняет геометрию.
- Фокус с клавиатуры сохраняется и становится графитовым; ошибка красная, успех остаётся зелёным.
- Не менять фотографии, логотипы, сетки, размеры, маршруты, обработчики, данные и подвал.

## Порядок внедрения и проверки

1. Снять исходные размеры 59 страниц на 1440 и 390 px, сохранить контрольные снимки и подвал.
2. Завести общие семантические цвета. Перевести используемые CSS на эти переменные, сохраняя служебные цвета статусов и медиа.
3. Уточнить роли основных/второстепенных кнопок, выбранных параметров, вкладок и форм; устранить цветную окантовку залитых кнопок.
4. Повторить обход, сравнить геометрию, проверить hover/focus/disabled, формы и сценарии покупки, визуально проверить контрольные страницы.
5. Выполнить существующие тесты и production build. Сохранить изменения отдельным коммитом и опубликовать для просмотра.

Исходный коммит: `83d6d83`. Локальные материалы аудита и временные скрипты в коммит не включать.

## Результат

- Используемые стили страниц, шапки и диалогов переведены на общие переменные палитры. Исторические CSS главной сохранены в прежнем порядке; версии ссылок обновлены, чтобы браузер получил новые цвета.
- `prototype/public/style-check/interface-palette.css` задаёт роли действий поверх исторического каскада, включая hover/focus и прозрачную границу залитых кнопок. `:where()` сохраняет одинаковую специфичность ролей; покупка следует после обычных действий.
- У покупки товара роль задана атрибутом `data-action-tone`: покупка красная, запрос для недоступного товара жёлтый. Обработчики не менялись.
- Подвал не перерабатывался. Контрольный снимок на десктопе совпал с исходным попиксельно.

Проверки: 79 файлов / 479 тестов прошли; после уточнения роли товара повторно прошли 14 тестов App/ProductDetail. Production-сборка прошла. Проверены 59 страниц на 1440 и 390 px: нет горизонтального переполнения, высоты совпали с исходными. Отдельно проверены цвета, прозрачные границы и hover кнопок, ошибки формы ремонта и сценарий товар → корзина → оформление → «Заказ принят».

Первый совместный запуск браузерного аудита и тестов превысил память компьютера; повторная проверка выполнена с одним worker и production preview. Это не ошибка приложения. Весь полный набор тестов повторно завершился успешно.
