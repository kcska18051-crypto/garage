## Как трактуем статусы

- «Реализовано по конспекту» — историческое сообщение о реализации, не новая независимая проверка.
- «Передано» — сообщение с ТЗ доставлено в чат; это ещё не подтверждение начала работы.
- «В работе» — разработчик подтвердил начало конкретного этапа.
- «Готово к проверке» — есть опубликованная версия и отчёт разработчика.
- «Проверено» — аналитический чат самостоятельно проверил результат по критериям.
- «На доработке» — обнаружены дефекты, разработчику передано воспроизведение.
- «Ожидает согласования» — отсутствует решение пользователя/клиента.

На момент записи новые пункты 1–12 переданы, но их реализация и готовность не подтверждены. Не считать их выполненными по прежним тестам или по наличию похожих блоков.

## Подтверждённые решения

1. Основной контейнер страниц согласован с шапкой и подвалом, центрирован на широком экране. Без гигантских hero, чрезмерных отступов, горизонтального overflow документа и перекрытых CTA.
2. Контрольные ширины: 2560, 1920, 1440, 1024, 390, 360 px. Внутренний горизонтальный скролл допустим для предназначенной для него карусели/таблицы.
3. Наличие показываем как «В наличии в N магазине/магазинах», без точных складских остатков в штуках.
4. Оформление заказа ориентировано на «ВсеИнструменты»: данные получателя, получение, оплата и итог в едином сценарии. На мобильном компактная панель итога/CTA над нижним меню с переходом к основному оформлению.
5. Бонусы «Спасибо» не добавлять. Программа лояльности скрыта до согласования.
6. Опции оборудования, варианты товара и сопутствующие товары — разные сущности. Опции расширяют оснащение совместимого оборудования; сопутка — отдельные расходники/принадлежности; напряжение/мощность могут быть вариантами, а не опциями.
7. Не выдумывать реальные адреса, фото магазинов, телефоны, кредитные условия, сроки, цены и обязательства. Не выдавать демонстрационную отправку/авторизацию/карту за production-интеграцию.
8. Для материалов сохраняются sidebar на desktop и внутренняя навигация на mobile; компактные баннеры 3:1, видео 16:9 без autoplay. Текст выровнен по левому краю основной колонки. Оглавление удалено: раннее требование содержания отменено. «Что изменилось»/«Практическое применение» удалены; «Читайте дальше» сохранено.
9. «О компании» оставлена для клиентского согласования без дополнительных правок; наличие страницы не означает финального одобрения дизайна.
10. Пользователь поручила после завершения самостоятельно проверить каждый пункт нового пакета, возвращать недоделки разработчику и выдавать итоговый отчёт с прямыми ссылками и статусами.

## База до новых правок

| Раздел | Статус и ограничение |
| --- | --- |
| Главная, каталог/фильтры, PDP, бренды, акции, поиск | Реализовано по конспекту; новые требования ниже ещё не приняты |

| Вход/регистрация/восстановление | Демонстрационный сценарий; временный вход без полей отключить после демонстрации |

| Контакты | Три демоточки и интерактивная схема; реальной карты/отправки по конспекту нет |

| Услуги: 1-й/2-й уровни, деталь, заявка | Ожидает согласования/актуализации ТЗ; по конспекту 02.10 ещё не передано |
| Privacy и реальные юридические тексты | Заглушка; требуется содержание клиента |

## Пакет правок 20.10 — 12 пунктов

Все пункты ниже имеют статус **«Передано; реализация и приёмка не подтверждены»**. Пользователь сначала попросила дождаться окончания списка; после её финального дополнения передан весь пакет.

| № | Требование | Проверяемый результат |
| --- | --- | --- |
| 1 | Акционные товары | По 2–3 акционных товара в товарных разделах с достаточным ассортиментом; заметный бейдж «Акция» на фото без пересечения с кнопками. Единые акция/цены во всех представлениях SKU. Не помечать весь ассортимент и не выдумывать скидки |
| 2 | Компактнее «Вы смотрели» | Уменьшить карточки на desktop: фото/отступы/общие габариты; сохранить читаемость и удобные кнопки. Ориентир 15–20% — предложение аналитика, не согласованный точный размер |
| 3 | Убрать очистку истории | Кнопка «Очистить историю» отсутствует в разделе на desktop/mobile |
| 4 | Самовывоз | Сразу доступны Ярославль, Вологда, Череповец. Выбран текущий город сайта; геолокация только с разрешения, отказ не блокирует ручной выбор. Город, пункты, карта, выбранный магазин и итог согласованы |
| 5 | Курьер: точка без адреса | Рабочая карта с постановкой/перемещением маркера и сохранением координат. Можно заказать на объект без почтового адреса; ориентир/комментарий. Сохранение при возврате между шагами, понятная ошибка загрузки карты |
| 6 | Транспортная компания | Выбор ТК из списка с отметкой, вариант «Своя ТК» с названием, адрес/терминал и итог согласованы. Один перевозчик на отправление — рабочее предположение аналитика |
| 7 | Адреса в профиле | В /profile/data сразу список сохранённых адресов, основной отмечен, управление работает; изменения отражаются в checkout и после reload. Понятное пустое состояние |
| 8 | Посадочные магазинов | У каждого магазина стабильный URL, описание, фото, контакты, часы работы, карта/схема проезда и маршрут. Переходы из контактов и самовывоза; общие данные магазина. Недостающие реальные данные явно демонстрационные |
| 9 | Инструменты корзины | Коммерческое предложение, кредит, поделиться корзиной. КП по выбранным позициям/количествам с предпросмотром и экспортом/печатью. Кредит — прототип заявки, без реальной заявки в банк/выдуманных условий. Ссылка корзины работает в чистой сессии, без персональных данных и автоматического затирания корзины получателя |
| 10 | Своя сопутка каждой строки корзины | У каждого товара отдельные релевантные рекомендации с добавлением. Для 1–2 строк блоки раскрыты; при 3+ по умолчанию раскрыт только верхний, другие можно раскрыть вручную. Количество строк, а не единиц. Без дублей SKU, итоги пересчитываются |
| 11 | Опции в описании PDP | Отдельный блок совместимого оснащения: фото, название, артикул, назначение, наличие, цена, количество и выбор нескольких опций к товару. В корзине понятна связь с основным товаром; базовая комплектация не меняется незаметно |
| 12 | Сопутка PDP | Самостоятельный блок расходников/принадлежностей, независимый от опций по данным и смыслу. Обычное добавление в корзину; не один и тот же набор под двумя заголовками |

### Передача и контроль

- Полное ТЗ из 12 пунктов успешно отправлено 20.10 в ранее использовавшийся чат `01a03d2b-85a3-7d31-8309-d9d746f4e3e5`.
- В прочитанном позднее конспекте 02.10 актуальный чат разработки указан иначе: «прототипы», `01a04713-ad10-7332-a725-dcda71f7f0e5`. До подтверждения получения актуальным исполнителем нельзя считать, что разработка началась. Проверить маршрутизацию и избежать параллельной реализации в двух чатах.
- Автопроверка «Гараж — приёмка 12 правок» создана в текущем аналитическом чате с интервалом 15 минут. На момент создания наблюдает ранее использовавшийся чат; адресата необходимо актуализировать после подтверждения.
- Отчёт разработчика должен содержать по каждому №: результат, опубликованный URL, commit SHA, сценарии/ширины проверки и ограничения.
- Независимая приёмка: проверить каждое требование и ключевые взаимодействия, 1/2/3+ строки корзины, опции и сопутку, свою ТК, точку без адреса, передачу корзины в чистый браузер. Найденные дефекты вернуть с воспроизведением и повторно проверить после исправления.
- Зелёные исторические тесты не доказывают готовность нового пакета. Проверки соразмерны изменениям; не повторять весь архив без причины.

## Остальные открытые решения

- Услуги: «Подбор автоэмали», «Сервисный центр», «Аренда оборудования/инструментов», затем список внутри направления и деталь с заявкой. Аренда компрессора вложена в аренду. Реальные составы сервиса/аренды и положение полиуретановых красок ждут клиента.
- Выпадающее меню: только «Каталог» или также пункты нижней строки шапки — ответ не зафиксирован.
- Подтверждение получения другим человеком — требуется решение клиента.
- Выбор поставщика карты, ключи и реальные данные магазинов — проверить доступность; статичная схема не закрывает новое требование интерактивной карты.
- Production-интеграции CMS/1С-Битрикс, банка, SMS, отправки форм и документов — отдельный этап; явно указывать границы прототипа.
- Стайл-чек и дальнейший дизайн продолжаем здесь. Новые конкретные решения по стилю пока не согласованы и не должны подменяться предположениями.

## Как продолжить

1. Прочитать этот реестр и handoff 02.10 вместо полного архива диалога.
2. Получить актуальную вершину codex/homepage-prototype, проверить рабочее дерево и не откатывать последующие изменения.
3. Подтвердить правильный чат разработки и получение пакета 1–12; не запускать две реализации.
4. Получать отчёт и независимо проверять опубликованные страницы. Обновлять статусы только с доказательствами.
5. После завершения сообщить пользователю итог по каждому пункту со ссылками, затем завершить автопроверку. Аналитику/дизайн и подготовку следующих ТЗ продолжать в текущем чате.
