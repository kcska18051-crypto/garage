# Связь услуг с ЛК — согласованный локальный прототип

Основание: пользователь ответила «делаем» на поток форма→заявка→ЛК/подробности/статус; поручение реализации передано 21.10. Прежнее ограничение на интеграцию с ЛК снято только для локального интерактивного прототипа. Sticky/query hotfix `c582e2f` завершён, CI289/public6widths PASS; этот этап отдельный.

## Поток и интерфейс

Три существующие формы создают запись в едином ProfileState. Номер/ID/дата/статус стабильны после reload. Успех показывает номер, исходный статус и кнопку «Посмотреть заявку в личном кабинете». Вошедший пользователь получает свою запись; гость не обязан регистрироваться, но для открытия подтверждает телефон заявки демонстрационным кодом1234 через существующий authflow. Чужой телефон/выход/прямой URL не раскрывают запись. Для несовпадения — нейтральное объяснение и кнопка повторного подтверждения, без показа телефона/имени/данных заявки.

Статический вход `/profile/services/request/?id=<stable-id>`: один реализованный шаблон детали в manifest даёт HTTP200 для произвольных локальных ID и refresh. Неизвестный/чужой ID — одинаковое понятное недоступное состояние без утечки существования. Личный раздел `/profile/services` остаётся единственным списком. Старые SR-104/SR-098/SR-082/SR-041 сохраняются в общем источнике; детали доступны ссылками, не параллельной модальной историей.

## Данные и статусы

Запись: ID/демономер, ISO-дата, тип, название/позиция, itemId, контакты, модель/проблема либо автомобиль/комментарий либо даты/количество/комментарий, признак приложенного фото и ownerPhone. При создании из профиля владелец — текущая демо-identity, контактный телефон может отличаться. Гостевая запись без владельца привязывается только к совпавшему нормализованному телефону после явного code-flow, не к произвольному password-demo или другому номеру. Нормализация:10цифр→7+номер;11цифр с8→7; остальные допустимые10–15цифр сохраняются.

Ремонт/автоэмаль: «Новая заявка». Аренда: «Ожидает подтверждения», не бронь. Дальнейшие этапы «Уточняем детали», «Согласовано», «Выполнено», «Отменено» показаны таймлайном/историческими демопримерами; пользователь не может имитировать решение менеджера. Новая механика отмены не добавляется.

## Локальность, фото и ошибки

Текстовые данные сохраняются только в этом браузере, без backend/SMS/API/оплаты. На форме до отправки явное предупреждение не вводить реальные персональные данные на общем устройстве; прототип не является безопасной авторизацией. Фото остаётся только в открытой форме; в историю сохраняется лишь факт приложения, не имя/оригинал/base64. До отправки, на успехе и в детали явно сообщается, что само фото не сохранено и после закрытия/reload недоступно. Предпросмотр/удаление/objectURL-cleanup сохраняются.

Сохранение атомарное: запись появляется в истории и успехе только после успешного localStorage.setItem. Quota/запрет хранилища — понятная ошибка и сохранённые поля для повтора, без ложного успеха. Повреждённый/чрезмерный JSON валидируется, приложение не падает; запись не должна молча перезаписать повреждённую историю. Лимит100 пользовательских записей и1500000 символов хранилища, текстовые поля ограничены; никаких больших изображений. Повторная отправка одного экземпляра формы имеет стабильный submissionId и не создаёт дубликат.
