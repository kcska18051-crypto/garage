Предыдущая реализация sticky: `f914f38`; её независимая приёмка отклонена. CSS/измерение шапки из неё сохранены, меню каталога не изменено.

## Первопричина и воспроизведение

Чистый receiver URL показывает товары и закрепляется. Точная ссылка независимой приёмки `receiver/?v=f914f38` воспроизводит дефект: `parseListingState` воспринимал каждый неизвестный query key как техническую характеристику товара. Получалось `specs.v=['f914f38']`, которому не соответствовал ни один товар. Пустая правая колонка давала grid высотой самой левой колонки (805,61px при viewport900). Sticky, правильно ограниченный родителем, в таком контейнере не имел свободного хода. Footer ещё не достигнут, но ограничение родительского grid уже достигнуто.

Публичное воспроизведение на 1440: при scrollY450 top167,03; при750 top−132,97; при1100 top−482,97. На1920/2560:173,5→−126,5→−476,5. Совпало с независимой приёмкой. Предки имеют overflow:visible; проблема не в скрытом scroll-container.

## Изменение

- Parser принимает явный набор допустимых ключей характеристик. Неизвестные `v`, `utm_source` и другие метаданные игнорируются.
- Общий hook передаёт ключи характеристик из полного исходного набора товаров текущей выдачи, не из уже отфильтрованного результата.
- Обычные технические фильтры, бренды, наличие, цена, tag/sort/view/page работают по прежнему механизму. Реальные несовместимые комбинации по-прежнему дают пустое состояние; sticky не вырывается из границ выдачи.
- CSS, меню каталога и конфигурация акций не менялись.
