# Одна страница оформления заявки на услугу

По согласованию с пользователем убран двухэтапный сценарий из заметки `2026-11-13-service-request-entry.md`: выбор → отдельная кнопка → модальное окно.

Теперь в `/profile/services/new` поля появляются непосредственно под выбранной услугой. Кнопки «Заполнить заявку» и модального окна нет. При смене позиции в одном направлении общие введённые данные формы сохраняются; повторное нажатие активной вкладки не сбрасывает выбор.

Публичные кнопки ремонта, подбора и аренды ведут в `/services/request?kind=…&item=…&from=…`. Услуга уже выбрана, повторный выбор скрыт за действием «Изменить услугу». Есть возврат на исходную страницу. Гостевое оформление сохранено; доступ к истории по-прежнему требует соответствующего подтверждённого телефона. Неверные параметры не создают произвольную услугу — показывается выбор из существующих данных.

Используется прежняя общая валидация, сохранение и защита заявок. Компонент формы поддерживает встроенное размещение без блокировки прокрутки, overlay и ловушки Tab. Старый модальный режим остаётся для изолированного использования/проверок, но публичные точки входа его больше не открывают.

После отправки видны номер, статус и следующий шаг отдельно для диагностики/ремонта, подбора цвета и аренды. Согласование стоимости/сроков не заменено оплатой, заявка на аренду не называется бронью. Прежние ограничения демонстрационного локального сохранения сохранены.

Проверки: последовательный прогон 49 связанных модульных тестов; 7 актуализированных браузерных E2E, включая три формы на 360/390/1440/1920 px, вход с другим/совпадающим телефоном, перезагрузку, выход, отказ хранилища и двойную отправку. Дополнительный браузерный проход встроенного оформления в ЛК, публичной предвыбранной услуги и возврата; 320 и 390 px без горизонтального переполнения. Production build проходит. Полный модульный набор также выполняется при публикации GitHub Pages.
