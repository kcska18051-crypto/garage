На ноутбуке откройте PowerShell и выполните следующее.

### 1. Проверьте, есть ли SSH-ключ

```powershell
Get-ChildItem "$env:USERPROFILE\.ssh"
```

Если есть файл `id_ed25519.pub`, новый ключ создавать не нужно — переходите к шагу 3.

### 2. Создайте ключ, если его нет

```powershell
ssh-keygen -t ed25519 -C "301205741+kcska18051-crypto@users.noreply.github.com"
```

На вопросы можно нажимать Enter. Пароль для ключа — по желанию.

### 3. Скопируйте публичный ключ

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub" | Set-Clipboard
```

Затем откройте:

[GitHub → Settings → SSH and GPG keys](https://github.com/settings/keys)

Нажмите **New SSH key**:

- Title: например, `Мой ноутбук`
- Key type: `Authentication Key`
- Key: вставьте скопированный текст

Добавлять можно только файл `.pub`. Файл `id_ed25519` — секретный, никому его не отправляйте.

### 4. Проверьте подключение

```powershell
ssh -T git@github.com
```

При первом подключении напишите:

```text
yes
```

В результате должно появиться приветствие для `kcska18051-crypto`.

### 5. Скачайте проект на ноутбук

Перейдите в папку, где хотите разместить проект, и выполните:

```powershell
git clone git@github.com:kcska18051-crypto/garage.git
cd garage
```

Если проект на ноутбуке уже скачан, вместо клонирования выполните внутри него:

```powershell
git remote set-url origin git@github.com:kcska18051-crypto/garage.git
git pull
```

На рабочем компьютере сейчас настроено HTTPS-подключение — оно продолжит работать. SSH-ключи у ноутбука и рабочего компьютера должны быть разными; каждый публичный ключ можно отдельно добавить в GitHub.

## Что точно предусмотреть в UX «Гаража»

1. Географию пользователя

Пользователь должен сразу понимать:

- для какого города показаны цена и наличие;
- где находится товар;
- когда его можно получить;
- доступен ли самовывоз;
- сколько будет стоить доставка;
- возможна ли доставка крупногабаритного оборудования.

2. Несколько способов найти товар

Нельзя строить путь только через большое дерево каталога. Необходимы:

- поиск по названию;
- поиск по артикулу;
- поиск по бренду и модели;
- подбор через категорию;
- подбор по характеристикам;
- подбор под задачу;
- переход из услуги к необходимым товарам.

3. Профессиональные фильтры

Фильтры должны меняться в зависимости от категории. Например, для подъемников важны тип конструкции, грузоподъемность, напряжение, высота подъема и назначение.

При этом нельзя переносить характеристики из разных источников без единой нормализации — иначе одинаковый параметр будет называться по-разному.

4. Информативную товарную плитку

Еще до перехода в карточку пользователь должен видеть:

- фотографию;
- название и артикул;
- ключевые характеристики;
- цену и старую цену;
- наличие;
- ближайшую дату получения;
- рейтинг;
- сравнение и избранное;
- кнопку покупки или запроса консультации.

5. Разные сценарии для простого и сложного товара

Расходники и недорогие товары можно покупать сразу.

Для дорогого оборудования может потребоваться другой путь:

```text
Товар → проверка совместимости → консультация
→ расчет доставки и монтажа → способ финансирования
→ коммерческое предложение или заказ
```

Это особенно важно для подъемников, шиномонтажного оборудования, оснащения рабочих постов и комплексных проектов.

6. Полноценную карточку товара

Базовые блоки:

- фотогалерея и видео;
- цена;
- наличие по складам;
- варианты получения;
- ключевые характеристики;
- полное описание;
- комплектация;
- документы и инструкции;
- гарантия и сервис;
- отзывы;
- вопросы и ответы;
- аналоги;
- расходники и запчасти;
- совместимые товары;
- информация о монтаже;
- лизинг, рассрочка или сплит — если применимо.

7. Разделение покупателей

Физическому лицу важны цена, доставка, оплата частями и простое оформление.

Юридическому лицу дополнительно нужны:

- цена для бизнеса;
- счет на оплату;
- реквизиты организации;
- документы;
- несколько получателей;
- сохраненные адреса;
- повтор заказа;
- персональный менеджер;
- коммерческое предложение;
- закупка большого количества;
- запрос специальной цены.

У «ВсеИнструменты» это различие видно даже в товарной выдаче: некоторые предложения помечаются как специальные цены для физлиц или юрлиц. [Пример каталога](https://www.vseinstrumenti.ru/tag-page/polomoechnye-mashiny-dlya-avtoservisa-2606037/)

8. Отдельное поведение отсутствующего товара

Если товара нет, карточка не должна становиться тупиком. Возможные действия:

- показать дату ожидаемого поступления;
- подписаться на поступление;
- запросить срок;
- подобрать аналог;
- заказать под поставку;
- получить консультацию.

9. Услуги как самостоятельные продающие направления

Для «Подбора автоэмали» и «Оснащения автосервиса под ключ» нужны отдельные сценарии, а не небольшие информационные страницы.

Например:

```text
Оснащение автосервиса
→ выбор типа бизнеса или рабочего участка
→ ввод площади, специализации и бюджета
→ получение предварительного состава оборудования
→ заявка на проектирование и расчет
```

Услуги необходимо связать с каталогом в обе стороны:

- из услуги — к подходящему оборудованию и материалам;
- из товара — к подбору, установке или комплексному оснащению.

10. Сценарий между устройствами

Поскольку пользователь может изучать дорогое оборудование несколько дней, желательно сохранять в аккаунте:

- избранное;
- сравнение;
- корзину;
- просмотренные товары;
- черновик заказа;
- запросы и коммерческие предложения.

## Основные пользовательские сценарии

Для дальнейшей аналитики предлагаю разобрать минимум восемь сценариев:

1. Покупатель знает точный артикул и хочет быстро заказать.
2. Покупатель знает задачу, но не знает подходящий товар.
3. Специалист сравнивает несколько моделей оборудования.
4. Владелец автосервиса закупает комплект оборудования.
5. Юридическое лицо оформляет заказ по счету.
6. Покупатель возвращается за расходниками или запчастями.
7. Нужного товара нет в наличии.
8. Пользователь заказывает подбор автоэмали или оснащение автосервиса.

Следующим шагом предлагаю подробно разложить каждый сценарий: точка входа → действия → развилки → результат → возможные ошибки → вопросы клиенту.

Первый принципиальный вопрос: **нужно ли делать на сайте явно переключаемые режимы «Частным покупателям» и «Для бизнеса», или различия должны появляться только в карточке товара, корзине и личном кабинете?** От этого будет зависеть вся верхнеуровневая архитектура сайта.

### Как устроены URL «ВсеИнструменты»

| Тип страницы | Формат | Пример |
|---|---|---|
| Каталог | `/category/название-ID/` | `/category/avtomobilnye-podemniki-4779/` |
| Категория + бренд | `/category/категория-ID/бренд-ID/` | `/category/avtomobilnye-podemniki-4779/nordberg-13775/` |
| Страница бренда | `/brand/бренд-ID/` | `/brand/nordberg-13775/` |
| Товар | `/product/название-товара-ID/` | `/product/stol-podemnyj-...-7020452/` |
| Отзывы товара | `/product/название-ID/otzyvy/` | отдельная индексируемая страница отзывов |
| Тематическая подборка | `/tag-page/запрос-ID/` | `/tag-page/polomoechnye-mashiny-dlya-avtoservisa-2606037/` |
| Доставка | короткий служебный URL | `/courier-delivery/` |

Пример страницы категории с брендом: [автомобильные подъемники NORDBERG](https://www.vseinstrumenti.ru/category/avtomobilnye-podemniki-4779/nordberg-13775/).

### Зачем в URL добавлены числовые идентификаторы

В конструкции:

```text
/product/stol-podemnyj-gidravlicheskij-nordberg-7020452/
```

есть две части:

```text
stol-podemnyj-gidravlicheskij-nordberg — понятный SEO-slug
7020452                                 — стабильный идентификатор страницы
```

Важное наблюдение: идентификатор в URL не совпадает с показываемым пользователю «кодом товара». Следовательно, это внутренний идентификатор страницы или товарной сущности.

Такая механика позволяет:

- однозначно находить страницу;
- изменять название товара без потери связи с ним;
- различать товары с одинаковыми или похожими названиями;
- не привязывать товар к текущей категории;
- безопаснее синхронизировать каталог с учетными системами.

Последнее особенно актуально для «Гаража», поскольку товары будут поступать из нескольких источников.

### Категория не входит в URL товара

Это сильное решение:

```text
/product/название-ID/
```

Вместо:

```text
/catalog/оборудование/подъемники/название/
```

Если товар перенесут в другую категорию, его URL не изменится. Значит:

- не пропадут поисковые позиции;
- не сломаются рекламные ссылки;
- не изменятся ссылки из заказов и писем;
- не потребуется массовая настройка редиректов.

Для «Гаража» товар тоже не следует физически вкладывать в дерево категорий.

### Фильтры отделены от SEO-страниц

Обычные пользовательские фильтры работают через параметры, но значительная часть таких комбинаций закрывается от индексации. В `robots.txt` отдельно ограничены URL с параметрами фильтрации, сортировки, сравнения, оформления заказа, избранного и личного кабинета. [robots.txt «ВсеИнструменты»](https://www.vseinstrumenti.ru/robots.txt)

При этом коммерчески значимые сочетания превращаются в самостоятельные страницы:

```text
/category/avtomobilnye-podemniki-4779/nordberg-13775/
```

То есть «Автомобильные подъемники NORDBERG» — не просто примененный фильтр, а отдельная SEO-страница.

Еще один тип — тематические посадочные:

```text
/tag-page/polomoechnye-mashiny-dlya-avtoservisa-2606037/
```

Они создаются под конкретный поисковый спрос.

- Техническое слово `category` можно заменить на понятное `catalog`.

1. Один товар — один постоянный URL.
2. Категория товара может меняться без изменения URL товара.
3. В URL не попадают цена, наличие и источник данных.
4. Артикул поставщика не используется как единственный внутренний идентификатор.
5. После публикации URL не удаляется бесследно — работает перенаправление.
6. Фильтры, сортировки и параметры рекламы не создают дубли страниц.
7. SEO-подборки создаются вручную под подтвержденный спрос.
8. Русские названия преобразуются в читаемую латиницу.
9. Служебные разделы, корзина и личный кабинет не индексируются.
10. Канонический адрес не зависит от выбранного города.

## 26.08.2026 09:55 — Codex

Это отдельный архитектурный сценарий — **мультискладской заказ**: товары одной корзины находятся на разных складах.

### Как может выглядеть сценарий

1. Пользователь добавляет два товара в корзину.
2. Система определяет:

   - товар №1 — склад Вологда;
   - товар №2 — склад Ярославль.

3. В корзине появляется уведомление:
   **«Товары находятся на разных складах. Заказ может быть доставлен несколькими отправлениями».**
4. Товары визуально группируются по отправлениям.
5. Пользователь выбирает доступный вариант получения.
6. Проходит авторизацию или регистрацию.
7. Выбирает доставку и оплату.
8. После оформления видит один заказ и отдельные статусы каждой части.

Например:

```text
Заказ №1245

Отправление 1 из Вологды
Товар №1 — передан в доставку

Отправление 2 из Ярославля
Товар №2 — комплектуется
```

### Возможные модели работы

**1. Один заказ — несколько отправлений. Рекомендованный вариант**

Пользователь оформляет и оплачивает всё один раз. Внутри заказ делится по складам.

Преимущества:

- понятное оформление;
- один номер заказа и одна оплата;
- в личном кабинете видны статусы каждой части.

Необходимо определить, как учитывать отдельные отправления в 1С и как рассчитывать их доставку.

**2. Автоматическое разделение на несколько заказов**

Корзина превращается в два заказа — по одному на каждый склад. Возможны отдельные оплаты и доставки.

Для внутренних систем это может быть проще, но для пользователя сложнее: несколько заказов, оплат и комплектов документов.

**3. Перемещение товаров между складами**

Компания сначала перемещает один товар на другой склад, а затем отправляет всё одной доставкой.

Для пользователя это удобно, но срок получения увеличивается.

### Лучший пользовательский вариант

Если логистика компании позволяет, можно дать выбор:

- **получить товары отдельными отправлениями быстрее**;
- **дождаться объединения товаров и получить одной доставкой позже**.

В корзине необходимо заранее показать:

- из каких складов будут отправлены товары;
- количество отправлений;
- срок каждого отправления;
- стоимость каждой доставки;
- общую стоимость заказа;
- можно ли получить заказ частями;
- что произойдёт, если одна из позиций станет недоступна.

Также потребуются сценарии частичной отмены, возврата одного отправления и возврата денег за отдельную позицию.

Главный вопрос клиенту: **осуществляет ли компания перемещение товаров между складами, чтобы объединить их в одну отправку?** От ответа зависит вся логика мультискладского заказа.

- свайп на мобильных устройствах;
- отдельные изображения для мобильной и десктопной версий;
- текст и кнопки должны быть HTML-элементами, а не частью изображения;
- анимация не должна мешать чтению и ухудшать скорость загрузки.

### 2. Строка преимуществ

Компактный блок из трёх-четырёх преимуществ, например:

- доставка по России;
- самовывоз из магазинов;
- гарантия и сервис;
- работа с физическими и юридическими лицами.

Показываем только подтверждённые преимущества. Непроверенные цифры и обещания не используем.

### 3. Популярные категории

Это динамический навигационный блок. Администратор сможет менять:

- состав категорий;
- порядок;
- изображение;
- название;
- ссылку;
- сезонный приоритет.

При этом основные категории не должны полностью исчезать из-за сезонных подборок. С главной должны оставаться прямые ссылки на важнейшие разделы каталога: внутренние ссылки помогают поисковой системе понимать приоритет страниц и структуру магазина. [Google Search Central рекомендует связывать главную с важными категориями и товарами обычными ссылками](https://developers.google.com/search/docs/specialty/ecommerce/help-google-understand-your-ecommerce-site-structure).

### 4. Бренды

По модели ТМК:

- сетка логотипов популярных брендов;
- логотип и название являются ссылкой;
- кнопка «Все бренды»;
- на мобильном устройстве — горизонтальная прокрутка либо компактная сетка.

Я бы не делала бесконечную карусель единственным способом просмотра: пользователь должен сразу видеть несколько брендов и иметь понятный переход в общий раздел.

### 5. Товарные подборки

Вместо блока только «Новинки» лучше заложить универсальный компонент с вкладками:

- Новинки;
- Хиты продаж;
- Акции;
- Рекомендуем.

На запуске можно оставить только «Новинки», а остальные вкладки подключить после появления правил формирования.

Для каждой подборки:

- 4 товара в одном ряду;
- до 8 товаров в двух рядах;
- отдельная кнопка «Все новинки» или «Смотреть все»;
- полноценные карточки с ценой, наличием, сравнением, избранным и добавлением в корзину.

Если вкладка не имеет отдельной содержательной страницы, универсальная кнопка «Все товары» ведёт в каталог. Если есть самостоятельная подборка, кнопка должна вести именно в неё.

### 6. Услуги

Две крупные карточки или баннера в одном ряду:

- подбор автоэмали;
- комплексное оснащение автосервиса.

На мобильном устройстве — одна карточка в ряд.

Каждая карточка должна содержать:

- название;
- короткое объяснение результата;
- изображение;
- кнопку «Подробнее» или «Оставить заявку».

Услуги не должны выглядеть как обычные товарные категории.

### 7. Юридическим лицам

Не просто рекламный баннер, а компактное B2B-предложение:

- заголовок;
- краткое описание формата работы;
- подтверждённые преимущества;
- кнопка «Подробнее»;
- дополнительное действие «Получить консультацию».

Этот блок ведёт на отдельную B2B-страницу, если клиент подтвердит её создание. До получения информации не указываем отсрочку, персональные цены или другие неподтверждённые преимущества.

### 8. О компании

Лучше сделать не декоративный баннер, а содержательный имиджевый блок:

- фотография магазина, команды или оборудования;
- короткий текст о компании;
- кнопка «Подробнее о компании»;
- факты в виде фичеров.

Например:

- лет на рынке;
- магазинов;
- товарных направлений или брендов;
- городов присутствия;
- собственный сервис — если подтверждено.

Этот блок создаёт доверие и одновременно даёт главной полезный текст без отдельного длинного «SEO-полотна».

### 9. Магазины и получение заказа

Рекомендую добавить отдельный блок:

- выбранный город;
- ближайшие магазины;
- адреса и режим работы;
- наличие самовывоза;
- ссылка «Все магазины»;
- при необходимости — карта.

Для регионального магазина это важнее, чем ещё один рекламный баннер.

### 10. Полезные статьи и новости

Визуально их можно объединить под заголовком «Полезное» и сделать переключатель:

- Статьи;
- Новости.

С точки зрения SEO это нормально при соблюдении условий:

- у статей и новостей есть отдельные страницы разделов;
- каждая карточка является обычной ссылкой;
- контент доступен без взаимодействия только с поиском или сложным JavaScript;
- вкладки не создают дубли страниц;
- по умолчанию лучше показывать полезные статьи, так как они помогают выбору товара.

Для SEO важнее не сам переключатель, а наличие постоянных URL и обычных внутренних ссылок. Google определяет структуру магазина прежде всего по связям между страницами. [Рекомендации Google по структуре интернет-магазинов](https://developers.google.com/search/docs/specialty/ecommerce/help-google-understand-your-ecommerce-site-structure).

Если новостей будет мало, их не нужно искусственно выделять в равноправный блок. Можно показывать четыре статьи и одну-две новости внутри общего раздела.

### 11. Отзывы

Добавляем только если клиент подтвердит:

- что отзывы действительно собираются;
- кто их модерирует;
- где они хранятся;
- какие отзывы выводятся: о компании, товарах или услугах.

На главной логичнее показывать отзывы о компании и обслуживании. Отзывы о конкретных товарах должны находиться в карточках товаров.

Если отзывов мало или процесс работы с ними не определён, лучше временно убрать блок, чем заполнять его формальными отзывами.

### 12. Финальный CTA

Да, он нужен. Для «Гаража» наиболее логичный вариант:

> Не уверены, какое оборудование или материал выбрать?

Действия:

- «Получить консультацию»;
- телефон;
- при необходимости — «Заказать обратный звонок».

Это полезнее универсального призыва «Оставьте заявку», потому что соответствует реальной проблеме посетителя.

### 13. Подписка

Подписку добавляем только после подтверждения рассылок. Если компания не будет регулярно отправлять полезные материалы и предложения, форма подписки станет лишним элементом.

Если рассылки подтверждаются, блок лучше расположить перед подвалом и предусмотреть:

- поле электронной почты;
- согласие на получение рассылки и обработку данных;
- ссылку на политику;
- подтверждение успешной подписки;
- обработку уже подписанного адреса и ошибок.

Итоговая архитектура получается логичной: главная не превращается в набор рекламных баннеров, быстро выводит пользователя в каталог, поддерживает товары, услуги и B2B-направление и создаёт прямые ссылки на важные страницы для поисковых систем. Подход соответствует рекомендации делать понятную иерархию и связывать важные страницы релевантными внутренними ссылками. [Google Search Central](https://developers.google.com/search/docs/appearance/sitelinks).

### Что важно поправить

1. Использовать термин «категория», а не «товары первого уровня»

Правильнее:

- категория товаров первого уровня;
- категория товаров второго уровня;
- детальная страница товара.

Иначе может показаться, что на каждом уровне находятся разные типы товаров, хотя речь идёт об иерархии каталога.

2. Не создавать лишние уровни каталога заранее

Страница категории должна появляться только тогда, когда в ней есть самостоятельный ассортимент и пользовательский спрос. Пустые промежуточные уровни усложнят навигацию и создадут слабые страницы.

Схема «категория → подкатегория → товар» соответствует рекомендациям Google для интернет-магазинов. Каждая индексируемая карточка товара должна быть доступна по обычным ссылкам из каталога, а не только через поиск или фильтры. [Google Search Central](https://developers.google.com/search/docs/specialty/ecommerce/help-google-understand-your-ecommerce-site-structure).

3. Карточку товара логически показываем внутри каталога, но URL не привязываем к категории

В клиентской структуре можно показать:

> Каталог → Категория → Подкатегория → Товар

Но технический адрес товара лучше делать независимым, например:

`/product/nazvanie-id/`

Товар может одновременно находиться в нескольких категориях или впоследствии быть перенесён. Независимый URL позволит не менять его адрес.

4. Услугам пока не нужен промежуточный уровень

Сейчас подтверждены две услуги. Поэтому логичнее:

- Услуги;
- Подбор автоэмали;
- Комплексное оснащение автосервиса.

Страница «Услуги второго уровня» понадобится, только если появятся самостоятельные направления, внутри которых будет по несколько услуг.

5. Статьи и новости стоит разделить внутри общего раздела

На главной они могут переключаться вкладками, но на сайте должны иметь отдельные страницы и постоянные URL:

- Полезное;
- Статьи;
- Новости;
- детальные страницы материалов.

6. Фильтры не включаем как отдельные страницы основной структуры

Обычная фильтрация — это состояние товарной выдачи. Отдельные SEO-страницы по фильтрам создаются позднее, только после сбора семантики и выбора полезных комбинаций. Иначе фильтры могут породить огромное количество дублирующихся URL. [Рекомендации Google по фасетной навигации](https://developers.google.com/search/blog/2024/12/crawling-december-faceted-nav).

## Почему это будет универсально

Мы избегаем сложных окончаний вроде «предназначен / предназначена / предназначено». Используем нейтральные конструкции:

- «Применяется для…»;
- «Подходит для…»;
- «Основные параметры…»;
- «Совместимые модели…»;
- «OEM-коды…».

Поэтому один механизм сможет работать с гайками, болтами, клипсами, переходниками, инструментами и оборудованием.

Для категорий настраивается не полный текст, а только:

- какие свойства относятся к назначению;
- какие — к совместимости;
- какие считаются ключевыми параметрами;
- порядок блоков;
- названия и единицы измерения;
- минимальное количество данных для создания описания.
