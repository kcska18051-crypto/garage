## Правило приёмки

- Наличие маршрута не означает, что страница готова: `PlaceholderPage` считается заглушкой.
- Каждая новая страница проверяется в опубликованной GitHub Pages-версии, а не только локально.
- Для широких страниц обязательна проверка на 2560 px: основной контейнер должен совпадать по ширине и координатам с контейнером шапки.
- Контрольные ширины: 2560, 1920, 1440, 1024, 390 и 360 px.
- На мобильных горизонтальный скролл допустим только внутри специально предназначенного rail, но не на уровне документа.
- Задача принимается только после unit/E2E/build, публикации, прямой ссылки и самостоятельной визуальной проверки.

## Что реализовано

### Основной сайт

- Адаптивная трёхуровневая шапка; третий уровень динамический.
- Если третий уровень скрыт, «Акции» остаются во втором уровне.
- Управляемая клиентом выборка акций в меню.
- Главная страница.
- Каталог первого, второго и третьего уровней.
- Компактные подкатегории третьего уровня.
- Полная товарная выдача: фильтры, активные chips, сортировка, плитка/список, пагинация, мобильный drawer.
- Детальная страница товара, варианты, галерея, увеличенный просмотр и панель покупки.
- Артикул копируется по нажатию; «Поделиться» является отдельным действием.
- Коммерческое предложение открывается поверх всех элементов страницы.
- Навигационная и детальная страницы акций; архив расположен внизу действующих акций.
- Страницы всех брендов и выбранного бренда.
- Поисковая панель с историей, подсказками и управляемыми промоматериалами.
- Отдельная страница результатов поиска.
- Корзина в компактной центрированной композиции.
- Полноценное сравнение товаров: категории, карточки, характеристики, режим различий, добавление/удаление/очистка и мобильный rail.
- Базовая форма обратной связи и состояние «Спасибо! Ваше сообщение отправлено».

### Правило наличия

- Не показывать точные складские остатки в штуках.
- Использовать формулировку `В наличии в N магазине/магазинах`.
- Другие статусы: `Под заказ`, `Доступно для заказа`, `Нет в наличии`, `Снят с производства`.

### Оформление заказа

- Корзина: https://kcska18051-crypto.github.io/garage/cart/
- Оформление собрано в единый сценарий по принципу «ВсеИнструменты».
- Получатель, способ получения, способ оплаты и итог находятся на одной странице.
- Способы получения: самовывоз, курьер и транспортная компания.
- Другой получатель раскрывается по переключателю.
- Для юридического лица используется организация/ИНН.
- На мобильном предусмотрена компактная панель с итогом и переходом к основной CTA над нижней навигацией.
- Бонусами «Спасибо» оплачивать нельзя; этот способ не должен появляться в прототипе.
- Актуальная версия checkout соответствует коммиту `3016c99`; при продолжении необходимо ещё раз открыть публичную страницу и проверить итоговую публикацию.

## Текущая обязательная очередь разработки

Эти задачи переданы в чат разработки, но на момент фиксации ещё не приняты. Пакет ЛК имеет приоритет над контентным разделом.

### 1. Документы в ЛК

Маршрут: `/profile/documents`.

Обязательно:

- пункт «Документы» в desktop- и mobile-меню ЛК;
- табы «Все», «Личные заказы», «Организации»;
- фильтр по организации, типу документа и периоду;
- поиск по номеру заказа/документа;
- статусы `Доступен`, `Формируется`, `Требует уточнения`;
- предпросмотр документа;
- загрузка доступна только для готового документа;
- пустые состояния и мобильная версия.

### 2. Помощь в ЛК

Маршрут: `/profile/help`.

Обязательно:

- пункт «Помощь» в desktop- и mobile-меню ЛК;
- поиск по вопросам;
- категории: заказы, доставка, оплата, возврат/гарантия, профиль/организации, услуги;
- FAQ accordion;
- действия «Задать вопрос», «Заказать звонок», «Написать в чат»;
- форма обращения с валидацией;
- успешное состояние и демонстрационный номер обращения.

### 3. Восстановление доступа

Маршрут: `/profile/recovery` либо самостоятельное состояние auth с прямым URL.

- Восстановление выполняется по подтверждённому телефону, а не через выдуманный пароль.
- Состояния: код верен, неверен, истёк, повторная отправка с таймером.
- «Нет доступа к номеру» ведёт в помощь.
- Нейтральная формулировка для неизвестного номера без раскрытия существования аккаунта.

### 4. Полноценное управление адресами

- Список адресов и метки «Основной», «Дом», «Работа».
- Добавление, редактирование, удаление с подтверждением и назначение основным.
- Нельзя бесконтрольно удалить единственный основной адрес.
- Поля: город, улица, дом, корпус, квартира/офис, индекс, комментарий курьеру.
- Демонстрационные адресные подсказки и «Показать на карте».
- Синхронизация сохранённых адресов с checkout.
- Полный mobile CRUD без перекрытия CTA нижней навигацией.

## Следующий пакет: Новости, статьи и обзоры

Выполнять после пакета ЛК.

### Архитектура

- `/news` и `/news/:slug`;
- `/articles` и `/articles/:slug`;
- `/reviews` и `/reviews/:slug`.

Три раздела имеют единый визуальный язык и вкладки, но отдельные URL и H1 для SEO. Переключение вкладки меняет маршрут.

### Листинги

- хлебные крошки, H1 и краткое описание;
- вкладки «Новости», «Статьи», «Обзоры»;
- компактные теги;
- сортировка по дате;
- сетка карточек;
- пагинация/«Показать ещё»;
- query-параметры для тега и страницы;
- минимум по шесть материалов каждого типа.

Карточка: изображение, тип/тег, дата, заголовок, анонс. Для статьи — время чтения; для обзора — объект обзора, возможный бейдж «Видео» и связь с каталогом.

### Детальные страницы

- хлебные крошки, тип/тег, H1, дата и время чтения;
- изображение по ширине контентной колонки, не огромный баннер;
- лид и текстовые блоки H2/H3;
- содержание с якорями для длинных статей/обзоров;
- материалы по теме;
- связанные категории/товары для статей и обзоров;
- новость использует более простой шаблон без искусственных блоков.

### Главная и footer

- На главной остаётся компактная карусель с вкладками и 3–4 карточками.
- Ссылка меняется: «Все новости», «Все статьи», «Все обзоры».
- В footer добавляется группа «Материалы».
- Товарные «Новинки» не смешиваются с новостями компании.

## Отложенные решения

- Бонусная программа ЛК скрыта до подтверждения клиентом.
- Не путать бонусную программу магазина с оплатой бонусами «Спасибо»: «Спасибо» в checkout запрещены.
- Окончательная механика подтверждения получения заказа другим получателем требует ответа клиента.
- Реальные телефоны, реквизиты, адреса, сроки, платёжные сервисы и карты не выдумывать; в прототипе используются демонстрационные состояния.
